# 浏览器塔防游戏设计思路文档

## 1. 项目定位

本项目是一款运行在浏览器中的战术塔防游戏原型，目标是在原创世界观和原创素材的前提下，尽可能复现《明日方舟》式塔防的核心体验：格子化战场、地面与高台部署、职业分工、阻挡数、费用管理、波次压力、撤退返费、漏怪扣生命以及高信息密度的战斗界面。

第一版不追求完整商业游戏体量，而是优先做出一局战斗的完整闭环。玩家需要在有限费用、有限部署位和不断推进的敌人压力下，判断何时部署、部署谁、放在哪个格子、是否撤退换位，并通过关卡后获得星级评价。

本文档采用“设计思路 + 开发规格”的综合结构。前半部分说明体验目标与系统取舍，后半部分给出可直接指导实现的数据结构、模块边界、交互规则与验收标准。

## 2. 仿作边界

项目参考的是《明日方舟》的玩法语言和界面节奏，而不是复制其具体 IP 内容。

允许借鉴的部分：

- 地面格与高台格的部署限制。
- 先锋、近卫、重装、狙击、术士、医疗等类似职业分工。
- 部署费用、自然回费、撤退返费、阻挡与漏怪生命系统。
- 菱形或格子化攻击范围显示。
- 顶部战况栏、底部干员卡组、暂停与倍速、结算星级等 UI 信息组织。
- 关卡时间轴、分波出怪、多路线压力与策略解题感。

需要原创化的部分：

- 角色名称、角色头像、阵营、剧情、语音、立绘、美术素材。
- 敌人名称、外观、设定文本。
- 关卡名称、世界观包装、UI 视觉主题。
- 技能名称与高级机制描述。

因此，文档中使用“干员”“职业”“部署”“阻挡”等泛化玩法术语，但所有可见内容应在实现时替换成原创素材与原创命名。

## 3. 核心体验支柱

### 3.1 部署即决策

玩家的主要乐趣来自部署前的判断，而不是部署后的频繁微操。每个格子的地形、朝向、范围、阻挡压力和费用节奏都应影响选择。第一版不做复杂主动技能，避免把体验重心从阵容部署转向技能连点。

### 3.2 地面阻挡与高台输出分工

地面单位承担拦截、承伤和近战输出，高台单位承担远程输出或治疗。敌人推进时，地面干员通过阻挡制造战线，高台干员利用范围覆盖形成火力区。飞行敌人无视阻挡，只能被远程单位处理，用来检验玩家是否建立了空中防线。

### 3.3 费用节奏制造压力

费用不是单纯资源数值，而是关卡节奏工具。开局费用有限，先锋提供额外回费，击败敌人返还费用，撤退返还部分费用。玩家应能明显感受到“早部署先锋换长期收益”和“直接部署强输出抢救防线”之间的取舍。

### 3.4 关卡是解题，不是堆数值

每张地图应有清晰的战术命题。例如新手训练场强调基础阻挡，十字路口强调多线调度，迷宫要塞强调路径长度与火力覆盖。敌人强度、路线、时间轴和地形组合应共同构成解法，而不是只靠敌人血量堆难度。

### 3.5 信息密度高但可读

界面应接近战术终端风格：紧凑、清晰、反应迅速。玩家在一屏内能看到费用、生命、波次、地图、干员费用、部署数量、选中单位信息、攻击范围和敌人路径。美术表现为系统服务，不用装饰性界面压过战斗信息。

## 4. 第一版 MVP 范围

第一版目标是完成一个稳定可玩的 2D Canvas 战斗原型。范围包括：

- Vite + 原生 JavaScript ES Modules 项目结构。
- 2D Canvas 战场渲染。
- JSON 地图加载，兼容 v1.0 与 v2.0。
- 三张默认地图：新手训练场、十字路口、迷宫要塞。
- 三类格子：路径格、高台格、障碍格。
- 多路径与时间轴出怪。
- 六类基础职业：先锋、近卫、重装、狙击、术士、医疗。
- 三类基础敌人：普通步兵、重装步兵、飞行兵。
- 部署、选中、撤退、范围显示、费用不足提示。
- 阻挡、近战攻击、远程攻击、治疗、飞行敌人规则。
- 费用、生命、波次、胜负、星级结算。
- 暂停、继续、重新开始、倍速切换。

第一版暂不作为主线目标实现：

- 3D Three.js 模式。
- 地图编辑器。
- 自定义干员与敌人编辑器。
- 主动技能、天赋、潜能、精英化、信赖等成长系统。
- 抽卡、养成、剧情、编队外部系统。
- 精细音效、角色语音、复杂动画演出。

这些扩展功能保留接口和数据兼容性，但不阻塞核心战斗闭环。

## 5. 技术栈与项目结构

### 5.1 技术栈

- 运行环境：现代浏览器，优先桌面端，兼顾平板横屏。
- 构建工具：Vite。
- 语言：HTML5、CSS3、原生 JavaScript ES Modules。
- 第一版渲染：2D Canvas。
- 二阶段渲染：Three.js 3D 模式，可与 2D 共享战斗状态。

## 6. 战斗场景与地图系统

### 6.1 网格

地图由二维网格组成，每个格子拥有类型、坐标和可选元数据。

格子类型：

| 类型 | 中文含义 | 部署规则 |
| --- | --- | --- |
| `path` | 地面/路径 | 可部署先锋、近卫、重装；敌人沿路径经过 |
| `high` | 高台 | 可部署狙击、术士、医疗 |
| `wall` | 障碍 | 不可部署，不可通行 |

第一版不额外区分朝向地形、特殊地块、禁部署路径格。为了让部署规则更接近《明日方舟》体验，允许玩家把地面干员部署在路径格上，并通过阻挡敌人形成接敌点。

### 6.2 路径系统

v2.0 地图支持多条路径。每条路径包含：

- `id`：路径唯一标识。
- `name`：显示名称。
- `entry`：入口坐标。
- `exit`：出口坐标。
- `points`：按顺序排列的路径点。
- `color`：调试或编辑器中的路径颜色。
- `lifeDamage`：敌人抵达出口时扣除的生命值，默认 1。

路径点应落在 `path` 格上。敌人从入口生成，沿路径点逐段移动，到达出口后从战场移除并扣除基地生命。

### 6.3 时间轴系统

v2.0 地图使用 `timeline` 配置出怪事件。事件字段：

- `wave`：波次号，从 1 开始。
- `startTime`：该事件在战斗开始后的触发时间，单位秒。
- `enemyType`：敌人类型 ID。
- `count`：生成数量。
- `interval`：同一事件内相邻敌人的生成间隔，默认 0.8 秒。
- `pathId`：敌人使用的路径 ID。

时间轴按绝对战斗时间触发，不依赖上一波是否全部消灭。这样可以稳定复现关卡压力，也便于倍速和暂停逻辑处理。

### 6.4 地图元数据

地图应包含：

- `version`：`1.0` 或 `2.0`。
- `id`：地图 ID。
- `name`：地图名称。
- `description`：简短战术提示。
- `width` / `height`：网格尺寸。
- `grid`：二维格子数组。
- `paths`：v2.0 多路径数组。
- `path`：v1.0 单路径兼容字段。
- `timeline`：v2.0 出怪时间轴。
- `initialCost`：初始费用。
- `maxCost`：费用上限，建议 30。
- `maxLives`：基地生命值。
- `totalWaves`：总波次数。

### 6.5 MapLoader 行为

`MapLoader` 需要：

- 兼容 v1.0 单路径地图，将其转换为 v2.0 内部结构。
- 校验地图尺寸、格子类型、路径点、时间轴字段。
- 对加载失败、JSON 解析失败、路径不存在、敌人类型不存在给出明确错误。
- 支持缓存已加载地图，避免重复请求。
- 加载失败时回退到内置默认地图，并在 UI 显示提示。

## 7. 默认地图设计

### 7.1 新手训练场

目标：教学基础部署、阻挡和远程覆盖。

设计要点：

- 单一路径，从左到右或上到下。
- 路径旁有少量高台格。
- 早期敌人为普通步兵。
- 中段加入少量飞行兵，引导部署狙击。
- 结尾加入一名重装步兵，测试持续输出和阻挡承压。

建议参数：

- 初始费用：12。
- 费用上限：30。
- 基地生命：10。
- 波次：3。

### 7.2 十字路口

目标：测试多线调度和费用规划。

设计要点：

- 两条路径在中部交叉或相邻经过。
- 关键地面格能同时影响两条线，但阻挡压力更大。
- 高台格覆盖交叉点，鼓励布置远程火力核心。
- 第二波开始双线错峰出怪。

建议参数：

- 初始费用：10。
- 费用上限：30。
- 基地生命：8。
- 波次：4。

### 7.3 迷宫要塞

目标：测试路径长度、火力覆盖和后期压力。

设计要点：

- 路径转折多，远程单位有多个可覆盖点。
- 地面部署点有限，重装位置选择影响成败。
- 重装步兵与飞行兵混合出现。
- 最后一波多路线压迫，要求玩家提前建立稳定防线。

建议参数：

- 初始费用：15。
- 费用上限：35。
- 基地生命：5。
- 波次：5。

## 8. 干员系统

### 8.1 设计原则

第一版干员以职业模板为主，不做复杂角色差异。每个职业提供一名默认干员，后续可以扩展为多名同职业角色。这样可以先验证职业生态和战斗闭环，再增加角色池。

干员共享字段：

- `id`：唯一 ID。
- `name`：显示名，需原创。
- `class`：职业类型。
- `deployType`：`ground` 或 `high`。
- `cost`：部署费用。
- `maxHp`：最大生命，高台远程单位可不参与受击，仍保留字段。
- `attack`：攻击力。
- `defense`：防御力。
- `attackInterval`：攻击间隔，单位秒。
- `block`：阻挡数。
- `range`：攻击或治疗范围。
- `targeting`：目标选择规则。
- `trait`：职业特性。

### 8.2 六种职业

| 职业 | 部署位置 | 阻挡数 | 攻击 | 攻击间隔 | 第一版职责 |
| --- | --- | --- | --- | --- | --- |
| 先锋 | 地面 | 2 | 低 | 1.5s | 低费开局、稳定回费、前期阻挡 |
| 近卫 | 地面 | 2 | 中 | 1.2s | 主力近战输出、补线 |
| 重装 | 地面 | 3 | 低 | 2.0s | 高生命与高阻挡，建立防线 |
| 狙击 | 高台 | 0 | 中 | 0.8s | 快速远程物理输出，优先处理飞行兵 |
| 术士 | 高台 | 0 | 高 | 2.5s | 慢速高伤输出，针对重甲敌人 |
| 医疗 | 高台 | 0 | 无 | 2.0s | 治疗范围内受伤地面干员 |

### 8.3 部署规则

- 总部署上限：8。
- 职业部署上限：先锋 2、近卫 3、重装 2、狙击 3、术士 2、医疗 2。
- 地面职业只能部署在 `path` 格。
- 高台职业只能部署在 `high` 格。
- `wall` 格不可部署。
- 已有干员的格子不可重复部署。
- 费用不足时不能部署。
- 达到总上限或职业上限时不能部署。
- 战斗结束后不能继续部署或撤退。

### 8.4 撤退规则

右键点击已部署干员触发撤退：

- 干员从地图移除。
- 返还 50% 部署费用，向下取整。
- 被其阻挡的敌人重新寻路沿原路径继续前进。
- 撤退不触发再部署冷却，第一版先保持简单。

### 8.5 攻击范围

近战干员默认只攻击自身格及被自身阻挡的敌人。

远程干员使用菱形范围，可用曼哈顿距离计算：

```text
abs(target.x - operator.x) + abs(target.y - operator.y) <= rangeRadius
```

第一版远程范围建议：

- 狙击：半径 3，优先飞行，其次最接近出口。
- 术士：半径 2.5 或等效格子模板，优先防御高或生命高的地面敌人。
- 医疗：半径 2.5，优先治疗生命百分比最低的受伤地面干员。

范围显示应在选择干员、悬停部署格、选中已部署干员时可视化。

## 9. 敌人系统

### 9.1 敌人字段

敌人共享字段：

- `id`：唯一 ID。
- `name`：显示名，需原创。
- `maxHp`：最大生命。
- `attack`：攻击力。
- `defense`：防御力。
- `resistance`：法术抗性。
- `speed`：移动速度，单位格/秒。
- `attackInterval`：攻击间隔。
- `canBeBlocked`：是否可被阻挡。
- `isFlying`：是否飞行。
- `rewardCost`：击败奖励费用。
- `lifeDamage`：进门扣除生命，默认继承路径。

### 9.2 三种基础敌人

| 类型 | 生命 | 速度 | 特性 | 击败奖励 |
| --- | --- | --- | --- | --- |
| 普通步兵 | 低，基准 `c` | 低速 | 无 | 3 |
| 重装步兵 | 高，约 `1.8c` | 低速 | 高防御 | 5 |
| 飞行兵 | 中，约 `1.2c` | 中速 | 无视阻挡，仅受远程攻击 | 5 |

第一版建议基准：

- 普通步兵：HP 100，攻击 12，防御 0，速度 1.0。
- 重装步兵：HP 180，攻击 18，防御 8，速度 0.65。
- 飞行兵：HP 120，攻击 0，防御 0，速度 1.25，不可阻挡。

### 9.3 移动与阻挡

- 敌人沿所属路径移动。
- 当地面敌人进入有地面干员的格子，且该干员当前阻挡数未满时，被加入该干员的阻挡列表。
- 被阻挡敌人停止移动，与阻挡者进入近战。
- 阻挡者撤退、死亡或敌人死亡时，阻挡关系解除。
- 飞行兵忽略阻挡格和地面干员，持续沿路径移动。

### 9.4 目标选择

默认目标选择规则：

- 近战干员优先攻击自己阻挡的敌人。
- 狙击优先攻击范围内飞行兵；没有飞行兵时攻击距离出口最近的敌人。
- 术士优先攻击范围内防御最高或生命最高的地面敌人。
- 医疗优先治疗范围内生命百分比最低的受伤地面干员。
- 敌人优先攻击阻挡自己的干员。

## 10. 战斗计算

### 10.1 伤害类型

第一版保留两种伤害：

- 物理伤害：`max(attack - defense, minimumDamage)`。
- 法术伤害：`attack * (1 - resistance)`。

建议最小伤害为攻击力的 5%，避免完全不破防导致战斗停滞。

### 10.2 攻击节奏

每个攻击单位维护独立攻击计时器：

- 计时器达到 `attackInterval` 后尝试寻找目标。
- 有合法目标则执行攻击或治疗，并重置计时器。
- 没有目标时计时器可保持就绪状态，目标进入范围后立即出手。

### 10.3 治疗

医疗不攻击敌人，只治疗地面干员：

- 目标必须在治疗范围内。
- 目标生命值低于最大生命。
- 治疗量使用医疗的 `attack` 字段。
- 高台干员第一版不被敌人攻击，因此不需要治疗高台单位。

## 11. 费用系统

### 11.1 基础规则

- 初始费用来自地图 `initialCost`。
- 费用上限来自地图 `maxCost`，默认 30。
- 自然回复：每秒 1 点。
- 击败敌人：获得该敌人的 `rewardCost`。
- 部署干员：扣除该干员费用。
- 撤退干员：返还 50% 部署费用，向下取整。

### 11.2 先锋回费

先锋被部署后，每 3 秒回复 2 点费用。多个先锋同时存在时各自独立计时。费用不能超过上限。

为了避免第一版数值失控，先锋回费应是可见但不压倒自然回费的收益。UI 可在费用栏显示短暂的 `+2` 反馈。

## 12. 游戏流程与状态

### 12.1 状态机

游戏状态建议：

- `loading`：加载地图与资源。
- `ready`：地图已加载，等待开始。
- `running`：战斗进行中。
- `paused`：暂停。
- `victory`：全部敌人生成并被清除，基地生命大于 0。
- `defeat`：基地生命归零。

### 12.2 胜负条件

胜利：

- 时间轴所有事件已触发。
- 已生成敌人全部被击败或离场。
- 基地生命大于 0。

失败：

- 基地生命小于等于 0。

### 12.3 星级评价

- 三星：胜利且没有敌人进入出口。
- 二星：胜利但至少漏过一个敌人。
- 失败：不授予星级。

第一版不需要一星，避免规则复杂。结算界面需展示击败数、漏怪数、剩余生命、用时和星级。

### 12.4 倍速与暂停

支持速度：

```text
0.5x -> 1x -> 1.5x -> 2x -> 3x -> 4x -> 5x
```

所有移动、攻击、治疗、出怪、费用回复、先锋回费都应受统一时间缩放影响。暂停时游戏逻辑时间停止，但 UI 仍可响应继续、重新开始等操作。

## 13. UI 与交互设计

### 13.1 总体风格

UI 方向是战术终端感：高对比、紧凑、清楚、少装饰。不要做传统塔防的卡通升级面板，也不要用过多营销式大卡片。界面应把“当前战局信息”放在第一位。

### 13.2 顶部信息栏

显示：

- 当前费用 / 费用上限。
- 回费状态或最近费用变化。
- 基地生命值。
- 当前波次 / 总波次。
- 当前地图名称。
- 游戏速度。
- 暂停 / 继续 / 重新开始按钮。

信息栏应始终可见，不遮挡地图关键格。

### 13.3 底部干员面板

显示所有可部署干员：

- 图标或职业色块。
- 名称。
- 职业。
- 部署费用。
- 已部署数量 / 职业上限。
- 是否可部署状态。

状态规则：

- 费用不足：按钮置灰，费用文本突出显示。
- 职业上限已满：按钮置灰并显示上限提示。
- 总部署上限已满：所有未部署按钮置灰。
- 当前选中干员：高亮边框。

### 13.4 地图交互

左键：

- 点击干员面板：选择待部署干员。
- 选择干员后点击合法格：部署。
- 点击已部署干员：打开信息面板并显示范围。
- 点击空白区域：取消选中。

右键：

- 点击已部署干员：撤退并返还费用。
- 右键默认浏览器菜单应在游戏画布内禁用。

悬停：

- 选择干员时，悬停格显示部署预览。
- 合法格显示可部署高亮。
- 非法格显示红色或禁用提示。
- 悬停预览同步显示攻击或治疗范围。

### 13.5 信息面板

选中已部署干员时显示：

- 名称。
- 职业。
- 生命值。
- 攻击或治疗量。
- 防御。
- 攻击间隔。
- 阻挡数。
- 当前阻挡数量。
- 部署费用。
- 职业特性。

信息面板不应覆盖底部干员面板；可放在右侧或浮动在地图边缘。

### 13.6 结算界面

胜利界面：

- 显示星级。
- 显示地图名、击败数、漏怪数、剩余生命、用时。
- 提供重新开始和返回地图选择。

失败界面：

- 显示失败原因：基地生命归零。
- 显示本局关键统计。
- 提供重新挑战。

## 15. 二阶段扩展

### 15.1 Three.js 3D 模式

3D 模式作为二阶段扩展，不影响第一版 2D 战斗完成。

设计要求：

- 通过“3D 模式”按钮在 2D / 3D 间切换。
- 共享同一套游戏状态，不复制战斗逻辑。
- 默认俯瞰战场，根据地图尺寸自动调整相机高度。
- 鼠标左键拖拽旋转视角。
- 滚轮缩放，范围 8 到 35 单位。
- WASD 或方向键平移相机。
- Q/E 旋转视角。
- R/F 升降高度。
- +/- 缩放。
- 支持立体网格、路径发光、太阳光、环境光、补光、阴影、抗锯齿。
- 性能监控显示 FPS、帧时间、内存，可关闭。

3D 模式的核心目标是展示感增强，不应引入不同于 2D 的判定结果。

### 15.2 地图编辑器

地图编辑器位于 `editor.html`，作为二阶段工具。

布局：

- 左侧工具面板：格子类型、绘制工具、路径工具。
- 中央画布：地图编辑与预览。
- 右侧属性面板：地图属性、路径管理、时间轴编辑。

功能：

- 绘制或填充 `path`、`high`、`wall` 格。
- 添加、删除、拖拽路径点。
- 管理多条路径。
- 设置地图名称、尺寸、初始费用、费用上限、生命值、总波次。
- 可视化编辑时间轴。
- 添加、删除出怪事件。
- 配置波次、开始时间、敌人类型、数量、间隔、路径。
- 导入和导出 JSON。
- 实时校验路径点与时间轴字段。

### 15.3 自定义干员与敌人编辑器

自定义编辑器位于 `custom-editor.html`，作为二阶段工具。

干员功能：

- 创建、编辑、复制、删除干员。
- 设置生命、攻击、防御、攻击间隔、部署费用、阻挡数。
- 设置攻击类型：物理、法术、精神。第一版战斗只使用物理与法术，精神类型预留。
- 可视化攻击范围：圆形、扇形、矩形、菱形。

敌人功能：

- 创建、编辑、复制、删除敌人。
- 设置生命、速度、攻击、防御、抗性。
- 设置颜色、精英标记、Boss 标记。

持久化：

- 保存到 localStorage。
- 支持导入和导出 JSON。
- 游戏启动时自动加载自定义数据，并与默认模板合并。

## 16. 性能与兼容性

### 16.1 性能目标

- 第一版在普通桌面浏览器稳定接近 60fps。
- 平板横屏可流畅运行，允许降低部分动画效果。
- 渲染与逻辑分离，避免 UI 更新阻塞游戏循环。

### 16.2 优化策略

- Canvas 绘制中缓存静态地图层。
- 动态实体单独绘制。
- 攻击范围只在选中或预览时绘制。
- 敌人和弹道可使用对象池。
- 日志系统可开关，默认生产模式关闭详细日志。
- 3D 模式中缓存材质与几何体，避免频繁创建对象。

### 16.3 错误处理

- 地图加载失败时显示明确提示，并回退默认地图。
- 数据校验失败时指出字段路径和错误原因。
- 战斗运行时异常应暂停游戏并显示错误面板。
- 控制台日志分级：info、warn、error、debug。

## 17. 验收标准

第一版完成时，应满足以下标准：

- 能通过 Vite 启动并在浏览器运行。
- 能选择三张默认地图之一开始战斗。
- 能部署六类干员，部署限制和费用限制正确生效。
- 能显示合法部署格、非法部署格和攻击范围。
- 敌人能按时间轴从指定路径生成并移动到出口。
- 地面敌人能被阻挡，飞行敌人不能被阻挡。
- 近战、远程、治疗、敌人反击都按攻击间隔运行。
- 费用自然回复、击败奖励、先锋回费、撤退返费正确。
- 漏怪会扣除基地生命。
- 全部波次结束后正确胜利，生命归零后正确失败。
- 胜利时能区分二星和三星。
- 暂停、继续、重新开始和倍速切换正确影响游戏逻辑。
- 地图加载器能兼容 v1.0 和 v2.0。
- 地图 JSON 错误能被捕获并提示。

## 18. 主要风险与取舍

### 18.1 范围风险

原始需求包含游戏本体、2D/3D 双渲染、地图编辑器、自定义编辑器和数据持久化，范围较大。第一版必须优先战斗闭环，把 3D 和编辑器放到二阶段，否则容易出现系统很多但核心玩法不可验证的问题。

### 18.2 规则复杂度风险

《明日方舟》的完整规则包含职业分支、技能、天赋、敌人能力、特殊地形、重量、嘲讽、隐匿等大量机制。第一版只保留部署、阻挡、费用、攻击、治疗、路径、波次这些底层规则，用少量职业模板形成可验证体验。

### 18.3 视觉相似度风险

项目目标是体验接近，而不是直接复刻 UI、角色和素材。实现时应避免使用原作图标、角色名、立绘、音效、UI 截图和剧情文本。视觉可以采用原创的战术终端风格。

### 18.4 数值平衡风险

浏览器原型中的数值不需要一次到位。应先保证规则正确和反馈清晰，再通过三张默认地图调节敌人生命、速度、费用、部署成本和波次时间。

## 19. 推荐实施顺序

1. 初始化 Vite 项目与基础页面。
2. 实现地图加载、网格绘制、坐标转换。
3. 实现游戏循环、时间缩放和暂停。
4. 实现敌人路径移动和时间轴出怪。
5. 实现干员部署、选中、撤退和范围显示。
6. 实现阻挡、攻击、治疗和死亡处理。
7. 实现费用、生命、胜负、星级结算。
8. 实现顶部栏、底部干员面板、信息面板和控制按钮。
9. 制作三张默认地图并调平基础数值。
10. 补充错误处理、调试开关和基础性能优化。
11. 验收第一版后再进入 3D 模式、地图编辑器和自定义编辑器。
